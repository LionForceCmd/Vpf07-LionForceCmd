# Локальный AI-агент

Домашнее задание модуля VPf07: терминальный AI-агент на OpenAI, который умеет искать
информацию в интернете, получать погоду и курсы валют, работать с файлами и помнить
историю диалога между запусками.

**AI-агент = LLM + инструменты + память.** Здесь это ровно три слоя из четырёх
архитектурных частей: модель принимает решения, инструменты выполняют действия,
память хранит историю. Управляющий цикл (исполнитель) написан вручную — весь код
агента помещается в пять файлов и читается целиком.

## Что умеет агент

| Инструмент | Что делает | Источник |
|---|---|---|
| `web_search` | поиск в интернете | DuckDuckGo (`ddgs`) |
| `get_weather` | погода сейчас + прогноз на 3 дня для любого города | Open-Meteo, запасной wttr.in |
| `get_crypto_price` | курс криптовалюты в обычной валюте | CoinGecko |
| `file_read` / `file_write` | чтение и запись файлов | локальная ФС |
| `get_fx_rate` | курс EUR/USD/RUB и других валют | open.er-api.com, запасной Frankfurter |
| `calculate` | арифметика, степени, математические функции | вычисление на месте |

Первые пять — обязательная часть задания. Последние два добавлены как дополнительные
инструменты из списка урока.

Ключи API не нужны ни одному инструменту: все источники бесплатные и открытые.
Единственный ключ — `OPENAI_API_KEY` для самой модели.

## Как запустить

Нужен Python 3.10+. Проверено на 3.13.

```bash
git clone <ссылка на репозиторий>
cd <папка>
python -m venv venv
venv\Scripts\activate          # Windows
source venv/bin/activate       # Linux / macOS

pip install -r requirements.txt
copy .env.example .env         # Windows   (cp на Linux/macOS)
# впишите в .env свой OPENAI_API_KEY

python run.py
```

Один запрос без диалога:

```bash
python run.py --log-info "сколько стоит bitcoin в рублях"
```

### Без ключа OpenAI

Если `OPENAI_API_KEY` не задан, агент не падает, а переходит в **offline-режим**:
инструменты работают как обычно, но вместо модели инструмент выбирает локальный
планировщик по ключевым словам. Так можно потрогать все инструменты и память
без единого потраченного токена. Этот режим используется и в тестах.

## Цикл агента

Ключевая часть проекта — `agent.py`. Один запуск `run()`:

```
        ┌──────────────┐
        │ 1. РЕШАЮ     │  модель получает системный промпт, память из memory.json
        │              │  и список инструментов, и решает, что делать
        └──────┬───────┘
               │ вернула вызовы инструментов?
        ┌──────▼───────┐   да
        │ 2. ДЕЛАЮ     │  агент выполняет вызовы и подставляет результаты
        │              │  в сообщения с ролью "tool"
        └──────┬───────┘
               │ хватает данных для ответа?
        ┌──────▼───────┐   нет — цикл повторяется (шаг ≤ MAX_STEPS)
        │ 3. ОЦЕНИВАЮ  │
        └──────┬───────┘
               │ да
        ┌──────▼───────┐
        │ ответ + запись│  весь диалог дописывается в memory.json
        │ в память     │
        └──────────────┘
```

Цикл ограничен `MAX_STEPS = 8`. Без ограничения модель может бесконечно звать
инструменты по кругу — агент будет жечь токены, не ответив пользователю. При
достижении лимита агент не молчит, а прямо сообщает, что задача не закрыта, и
показывает результат последнего инструмента.

Ошибка инструмента не обрывает цикл: текст ошибки уходит модели обратно, и она может
исправить аргументы или выбрать другой инструмент.

## Инструменты и function calling

Каждый инструмент — обычная функция Python, возвращающая строку. Рядом лежит её
JSON-схема в формате OpenAI (`TOOL_SCHEMAS`). Обе структуры собраны вручную:

```python
TOOLS        # имя -> функция; по ней агент исполняет вызов модели
TOOL_SCHEMAS # описание для модели: что за инструмент и какие у него аргументы
```

Модель видит `TOOL_SCHEMAS` и сама решает, что вызвать и с какими аргументами.
Агент выполняет вызов через `call_tool` и кладёт результат в диалог.

`call_tool` **никогда не бросает исключения**: неизвестный инструмент, битый JSON
в аргументах или недоступный API превращаются в текст `ОШИБКА (...)`, который
уходит модели обратно. Благодаря этому цикл не разваливается из-за одной неудачи.

### Три решения, которые стоит отметить

**Коды погоды переводятся в текст.** Open-Meteo отдаёт `weather_code: 71`. Без
таблицы WMO модель получила бы число и не смогла сказать пользователю, что это снег.

**Названия монет и валют нормализуются.** Пользователь пишет `btc`, а CoinGecko
ждёт `bitcoin`; `$` превращается в `usd`, `руб` — в `rub`. Без этих словарей модель
пришлось бы угадывать идентификаторы, и ошибки выглядели бы как «API не отвечает».

**У каждого внешнего источника есть запасной.** В курсе показана ошибка
`Geocode timeout`, из-за которой агент не мог ответить на вопрос о погоде. Здесь
сбой основного провайдера не ломает инструмент, а переключает на резервный:

- погода: Open-Meteo → wttr.in;
- курсы валют: open.er-api.com → Frankfurter (данные ЕЦБ).

Запасной источник выбран не случайно: **ЦБ ЕС с 2022 года не публикует курс рубля**,
поэтому в Frankfurter его нет — для домашнего задания с EUR/USD/RUB основным
источником пришлось выбрать другой.

## Файлы

Агент работает только внутри папки проекта: путь из аргументов модели приводится
к абсолютному относительно неё, а выход через `..` блокируется. Это заодно решает
ошибку `File not found` из курса — там относительный путь искался не с того места.

`calculate` выполняет выражения через `ast` по белому списку: только числа,
арифметика и математические функции. Ни импортов, ни атрибутов, ни вызовов вроде
`open()` — попытка выполнить чужой код отклоняется (проверяется в тестах).

| Файл | Назначение |
|---|---|
| `agent.py` | цикл «Решаю — Делаю — Оцениваю», системный промпт |
| `tools.py` | инструменты и их JSON-схемы |
| `llm.py` | вызов OpenAI и offline-планировщик |
| `memory.py` | долговременная память в `memory.json` |
| `run.py` | CLI, команды, логирование |
| `tests.py` | 80 проверок без сети и без ключа |
| `memory.example.json` | пример файла памяти в формате агента |

## Память

`memory.json` переживает перезапуск: вчерашний диалог виден сегодня.

```json
{
  "version": 1,
  "created_at": "2026-10-15T12:00:00",
  "updated_at": "2026-10-15T12:00:41",
  "sessions": [
    {
      "id": 1,
      "started_at": "2026-10-15T12:00:00",
      "turns": 4,
      "messages": [
        {"role": "user", "content": "какая погода в Москве", "timestamp": "..."},
        {"role": "assistant", "content": "...", "timestamp": "...",
         "tools_used": ["get_weather"]}
      ]
    }
  ]
}
```

Что важно в реализации:

- **В модель уходит не весь файл**, а последние 20 сообщений текущей сессии.
  Иначе контекст быстро переполнится и запрос станет дорогим.
- **Сессия продолжается в тот же день и начинается заново на следующий.** Так в
  файле остаётся честная история по дням, а не один растущий список.
- **Запись атомарная**: сначала рядом пишется временный файл, потом он заменяет
  основной через `os.replace`. Внезапное закрытие терминала не оставит обрезанный
  `memory.json`.
- **Битый файл не роняет агента** — он откладывается как `memory.json.broken`,
  а агент начинает с чистого листа.
- **Записывается `tools_used`** — по истории видно, на каких данных строился ответ.

## Логирование

Каждый шаг цикла логируется в `agent.log`: какой инструмент вызван, с какими
аргументами, сколько отработал, что вернул. Именно логи в курсе показали, где
ломается агент — без них ошибка `File not found` выглядит как «модель неправильно
поняла задачу».

```bash
python run.py --log-info "погода в Москве"
```

Подробный лог в консоль включается флагом `--log-info`; в файл он пишется всегда.

## Команды CLI

| Команда | Действие |
|---|---|
| `/tools` | список инструментов |
| `/stats` | состояние `memory.json` |

## Тесты

```bash
python tests.py
```

80 проверок, **без сети и без `OPENAI_API_KEY`** — инструменты, ходящие в интернет,
подменяются заглушками. Покрыты:

- реестр инструментов и корректность схем function calling;
- калькулятор, включая блокировку выполнения произвольного кода;
- работа с файлами и защита папки проекта;
- нормализация названий монет и валют;
- память: перезапись файла, окно контекста, новый день, битый JSON;
- офлайн-планировщик: выбор инструмента по тексту запроса;
- агентный цикл: сборка запроса, исполнение инструментов, лимит шагов;
- сборка запроса к OpenAI (на подделке SDK-ответа).
